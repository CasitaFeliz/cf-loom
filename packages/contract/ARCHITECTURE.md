# Internals of @casitafeliz/loom-contract

How the package's `src/` is split into modules, as [Package layout](../../ARCHITECTURE.md#package-layout) in the root ARCHITECTURE.md requires. The entries `src/index.ts` (`.`) and `src/internal/index.ts` (`./internal`) re-export from the modules' `index.ts`.

The package builds with `lib: ["ES2024", "WebWorker"]` and no Node types: `wire/` reads web-standard `Request`, `Headers`, `URL` and streams, which the WebWorker library declares without a browser window's globals (`window`, `document`, `localStorage`), so nothing in it can lean on a page or on Node.

## Modules

| Module | Holds | Depends on |
| --- | --- | --- |
| `declarations/` | every `define*`, its types and type rules, the runtime consts beside the types (`http`, `element`, Standard Rejections, the reserved codes), Attachments, inference types, predicates, the freeze, the `deprecatedAt` stamp's format | none (reads the Snapshot's types for `ContractPackage`; type only) |
| `open/` | Open Enums: `openEnum` and `isOpen`, and `openEnumReader`, an Open Enum's Reader schema, which writes its Unknown case back as its text | none |
| `issues/` | a value parsed with its schema, or written back through a Reader schema, zod's failures as cf-loom's issue codes; a party's declared parts, an Endpoint's Input or a Guard's demands, parsed under their fields; an Endpoint's Guards' demands read in Attachment order, the first that fails alone | `declarations`, `validation` |
| `walker/` | zod schemas to Snapshot nodes; the Not allowed rules judged on walked nodes and slots (open intersections, records keyed by an enum or literal) | `open` |
| `validation/` | every rule `generate` enforces, the valid result, and a failure as one line; the parts a declaration holds schemas in, the Rejections an Endpoint or Guard answers, found by the code each resolves to, the code, status and message each resolves to, and the Standard Rejections a root resolves; `Issue`, one way a value broke its part; what the runtime reads of a valid root: its Endpoints in Group order, their Attachments with their Qualifiers, a path's segments, and the text parts of a Contract's Endpoints and Guards walked once and judged by every text-part rule `generate` applies, header names included | `declarations`, `walker` |
| `wire/` | the Wire protocol's rules `serve`, the client and the fakes share, free of Handlers and hosts: the request side, matching a method and path to a declared Endpoint, reading a party's text parts and reading a request's body within `maxBodyBytes` and a response's whole, by one reader, a stream that fails told from no JSON; a text part's value from its texts by node and a value as text, a number in plain decimal, which text can travel as a header, a path segment or a query value, a segment encoded and decoded, a party's headers read into values by their nodes, and a Success's or an Input's headers as text or Issues; a received body read whole, a stream that already failed discarded without a throw; the Envelopes and reading one from a received body, the reserved codes with their statuses, `committed` and texts, `Internal error`, the status a Fault travels with, the invalid-input body from Issues and its reader, its `in` and `code` as Open Enums, the schema a Rejection's body is read with, the JSON content type and the `Deprecation` header, written and read back; the response side, a `Response` from a Success, a Rejection, the invalid-input Rejection's Issues, a Fault or a reserved code | `declarations`, `open`, `walker`, `validation` |
| `snapshot/` | the declared Snapshot of a valid root, its types, the exported Snapshot's included, and its canonical text; an exported Endpoint's entry, found by identity, and the nodes its text parts are read by | `declarations`, `walker`, `validation` |
