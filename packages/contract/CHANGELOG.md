# @cf-loom/contract

## 1.0.0-rc.2

### Patch Changes

- dbab5a7: `generate`, `check` and `publish` judge whether a plain union or an intersection reaches an Open Enum, and `check` and `publish` refuse a Baseline holding a def that leads back to itself through `ref`s, `union` options and `allOf` items alone; both now take time that grows with the defs, instead of its square.
- 82776d6: The contract README's orders Group lists `editOrder` and `listOrders`, the Endpoints its examples declare, and the server README's `main.ts` gives its Resources `permissions`, which the handlers README's permission Guard takes, so the Service the READMEs describe is one that `cf-loom generate` accepts.
- ecd2a47: `sqs()` from `@cf-loom/messaging/sqs` runs a Service's messaging on SNS/SQS, through the organization's SNS and SQS clients: `publish` sends each Message to the Service's SNS topic, and `consume` receives from each Durable consumer's SQS queue, after checking the queue and its subscription against what `applyBrokerPlan` writes. A Message cf-loom cannot read is never deleted, but left for the queue's dead-letter queue. `@cf-loom/contract` gives the wire its ASCII JSON for a Message's ids and Transport headers in SNS message attributes.
- 7a3d3f9: A value nested past the call stack is one `malformed` Issue at its root in every engine, and no other throw is read as one. In Firefox, whose overflow is an `InternalError`, the client returns the `INVALID_OUTCOME` Fault or its `INVALID_INPUT` Rejection instead of throwing on such a value. A getter or Proxy trap of a value a Caller or a Service builds that throws a `RangeError` for another reason, such as `Invalid array length`, throws as any other error does, instead of being read as `The value is nested too deeply to read`.

## 1.0.0-rc.1

### Major Changes

- 61db56f: An intersection that is no merged object holds each shape once, in the order of the items' shapes, the left item kept with its annotations, so a description no longer reorders or merges an `allOf`'s items. A Snapshot whose `allOf` items are in another order, or hold one shape twice, is malformed. The Compatibility Check compares annotations inside plain unions, tuples and `allOf`s position by position, so an annotation moved between two items of one shape is a Neutral Change instead of making `check` and `publish` fail with `The Snapshot changed but no Change was found: a bug.`
- d71925d: A Definitions Package's Guard or Rejection added or removed is one Change, at its export, which Services import by name. The Check no longer adds a second Breaking `removed` at `codes.<code>` or `guards.<name>`. A code no export names but a kept Guard answered, once removed, is that Guard's Additive `rejection-removed`. A Guard no export names, added to or removed from a kept Guard's `guards`, is only that Guard's Neutral `guards-changed`: adding one bumps patch where it bumped minor, and removing one is no longer Breaking.
- 2ea2153: The invalid-input Rejection's body lists at most 100 Issues within 64 KiB of JSON, the first ones the Provider read, and counts every other one in a required `omittedIssues`, so a small request can no longer get a Response many times its size. `serve`, the client's unsent Rejection and the fake Provider write the same body; `@cf-loom/testing`'s `InvalidCall` is that body, `{ issues, omittedIssues }`, and a step that scripts the invalid-input Rejection gives `omittedIssues`. Upgrading cf-loom adds `omittedIssues` to every Service's Snapshot, an Additive Change on its invalid-input code; a Reader generated with it reads an older Provider's body as `INVALID_OUTCOME`.
- 93dd25e: `generate` refuses a regex that is no plain RegExp, given to `.regex()`, as a format's `pattern` or as `z.url()`'s `hostname` or `protocol`: a subclass, a RegExp of another realm, one with a property of its own besides `lastIndex` such as its own `test`, or no RegExp at all, which zod tests through its own `test` while the Snapshot held only its source and flags. A Proxy around a RegExp is refused instead of crashing `generate`, and a string given to `.regex()` no longer writes an empty `regex`.
- e464942: Each refusal sentence a declaration's type error and `generate` both write is written once, so the two always agree. Changed type errors:
  
  - A reserved Endpoint, Guard or Subscription name reads `<An Endpoint / A Guard / A Subscription> name is camelCase words and no reserved word: "delete"`.
  - An Application depending on an Endpoint that is not Public reads `An Application depends on Public Endpoints only: payments-service's getPayment is internal`.
  - Every rule's sentence is a key no value has, so a Guard's `demands.params` or `demands.body` written as the sentence's text is a type error too.
  
  A Provider is another Service. A Service listing a Dependency on, or a Subscription to, an Element of its own Contract Package fails `generate` with `A Provider is another Service: orders-service is this Service`, and either is a type error on `defineService`.
- 71750b6: `generate` refuses every string format check zod runs through a function, whatever pattern sits beside it: any `z.stringFormat()` (a regex given to it included) and the formats zod builds from a regex, `z.hex()`, `z.hostname()`, `z.currencyCode()` and `z.hash()`. The last four are named by every spelling that builds them (`z.hex() or z.stringFormat("hex")`), each with `(use .regex(z.regexes.<name>))`. Write `z.string().regex(z.regexes.hex)` (or `z.regexes.sha256_hex` for `z.hash('sha256')`): the Snapshot then holds the regex, and OpenAPI and AsyncAPI documents a `pattern` instead of a `format`. The Snapshot format 1 no longer knows the formats `hex`, `hostname`, `currency_code` and the hash formats, so a Snapshot holding one is malformed.
- 12a443e: `generate`, and `serve` at startup, refuse a text part's enum whose values travel as one text, such as `1` and `'1'`, `true` and `'true'`, or `1e21` and `'1000000000000000000000'`: a Caller could never send the second. The line reads `A query param's values each have a text of their own: v has "1" and 1`, rule `shared-text`.
- 9b9cfde: `generate`, and `serve` at startup, refuse a text part's enum holding a value whose text its part cannot carry, in an Input, a Guard's demands, a Success or a Rejection: no Caller could send it, and no Outcome holding it would be valid. A header's value must be HTTP field text (not `' 1'`, `'é\n'` or `'€'`), a path param's a segment that is not `''`, `.` or `..`, and a query value or a path param well-formed (no lone surrogate). One line names every such value of a field, `A header's values each travel as HTTP field text: x-s has " 1" and "é\n"`, rule `unsendable-text`. A `z.string()` with a regex, a format or a length keeps passing: its values are not closed, and the runtime refuses each one as it is sent.

### Minor Changes

- 8d566ea: The Wire protocol gives the names of the SNS message attributes a Message travels in on SNS/SQS.

### Patch Changes

- e592e51: `generate` walks and validates a chain of ids, each holding the next, in time and memory that grow with its length instead of its square, so a deep chain that passes, or fails at one place, no longer runs out of memory with no line saying why. A chain whose every link fails still prints one line per link, each naming its full location, so that output grows with the square of the chain.
- 6edd65b: The Compatibility Check, which `cf-loom check` and `cf-loom publish` run, compares a chain of ids, each holding the next, in time and memory that grow with its length instead of its square, so a long chain that is unchanged, or changed at one place, no longer runs out of memory.
- 230b4a3: The Snapshot decoder no longer throws `RangeError` on a Snapshot holding an array or map of more than about 120,000 items, and the client and `@cf-loom/testing` refuse an Endpoint's exported Snapshot cut nested past 256 levels as `<provider>'s exported Snapshot is malformed: <path> nests deeper than 256 levels` instead of throwing `RangeError`.
- 0fd9500: The Compatibility Check, which `cf-loom check` and `cf-loom publish` run, compares a chain of ids through a plain union, a tuple item or an `allOf` in time that grows with its length instead of its square.
- ae3e590: The READMEs write the glossary's terms as CONTEXT.md spells them, such as Direct call, Former Input, Readers file, Fake Provider and Broker plan, and the messaging README's section "Applying the plan" is "Applying the Broker plan". The messages that name the Broker plan spell it so: `apply the Service's Broker plan` when a Stream or Durable consumer is missing, `<root> has no Broker plan: …` from `cf-loom broker-plan`, and `The value is not the Broker plan of the document cf-loom broker-plan --json prints: …` from `applyBrokerPlan`, which no longer calls the value "the plan" alone.
- bbc91bc: A removed field whose schema is an `allOf` of `ref`s no longer makes `publish` write a Snapshot that `check` refuses as malformed: a former Input's graft holds every node it writes as the Snapshot does, an `allOf`'s items in shape order and each shape once, when it names a def apart or follows an alias def to the def it leads to.
- 00ab03c: A Handler's `request.signal` aborts when the Caller leaves even after a garbage collection: `nodeHttp`, `nodeListener` and `fastifyServe` hold each request's `Request` from the Caller's departure until its response ends, where undici's `Request` stopped following that signal once nothing else held it. A client call holds its Request from its `signal` the same way until the call settles, so an abort reaches any `fetch`, `serve` in the same process included.
- d2383fe: A request, a Success or a Rejection body with very many items that each break their schema no longer throws `RangeError` from the Issues' collection: `serve` answers `INVALID_INPUT` with every Issue, `client` returns the `INVALID_OUTCOME` Fault or its own `INVALID_INPUT` Rejection, and a Handler's Success of that kind is reported as `invalid-outcome`, not as the Handler's throw.
- a3b1910: A list of three or more names in a failure line is written `a, b and c` by one helper, where two lines wrote `a and b and c`: a Root file that exports three Roots, and a code three or more sources declare.
- d9601a0: Rules that several packages wrote out separately, such as the broker needs of a Contract and the reserved header names, now live in one place, with no change to what cf-loom reads or writes.
- 49121db: The TypeScript blocks of the client and testing READMEs compile with those of the contract, handlers, messaging and server READMEs against one Service, and their tests run them: the client README's first example is a whole file exporting `payments` and `amountOf`, its Provider-side files name `payments-service/` and import what they use, and its browser example is a file of `web-admin` calling through `adminPaymentsDependency`; the testing README's examples import the Handler they call from `src/endpoints/orders/`; the contract README's Definitions Package exports `idempotencyKey`, its Dependency lists `createPaymentEndpoint` and its orders Group lists `settlePayment`; and the server README's `main.ts` gives its Resources the `payments` client.
- 6d3a5df: The CLI and contract READMEs use the glossary's terms, such as the Readers file, and the contract README gains a first-declarations example of an Endpoint, a Group and a Root.
- 80bd46e: The READMEs gain Set up steps, a CI recipe that keeps `cf-loom check`'s exit status, and a Retrying section that says which Faults a Caller retries and what a browser Caller needs exposed.
- 30a4343: The TypeScript blocks of the contract, handlers, messaging and server READMEs compile together against one Service; the GuardHandler example rejects with the `www-authenticate` header its Rejection declares, and the server and messaging examples hand `serve` and `consume` the Resources their Handlers take; and the contract README's first declarations are those of `notes-service`, a small Service of its own. `onServiceFault`, `onAnswered` and `onBrokerTrouble` may return a value, which is awaited and ignored.
- ea89c85: The version bump no longer caps a refused Change at patch: `check` and `publish` report a refused Change and derive no version, so the cap was never reached.
- c2bd88c: `generate` no longer tells a `.meta({ id })` on a schema that lies on a cycle that it lies on no cycle when the cycle's only way back runs through a schema it already walked, such as a def that fails, a def a failure above it dropped, a cycle no id names, a second schema with a taken id, or a schema a second declaration walks afresh; the verdict no longer depends on the schema the walk enters first. A schema with a recursion id the walk accepts is walked once, whatever it fails by, so a Contract whose ids off a cycle, or cut for their depth, each hold the next twice no longer takes time exponential in their number, and a second schema with a taken id reached at several places is told once, at the first, with the others in `alsoIn`.
- 31b52ef: `generate` refuses a value that is no zod 4 schema inside a schema, such as a zod/v3 schema in an object field, in a discriminated union's variant or as a JSON-shaped union's record key, with `not allowed: a value that is no zod 4 schema (zod/v3 is not read)` at its place instead of crashing with a `TypeError`, beside any line the surrounding schema earns on its own, and a field holding one is a type error. A cycle whose `.meta({ id })` is refused (not camelCase, not a string, or beside another refused key) gets that refusal alone, not a second `a cycle without .meta({ id })` line, and a cycle whose camelCase id a later `.describe()`, `.meta()` or check dropped names that id and says to put `.meta({ id })` last.
- 2a50fef: Every line a library writes stays one line: a key, a name, a path, an id or a message holding a line break, such as a record key a Caller sends that `serve` logs in an Issue, no longer splits an Error's message or a console line in two. Each of CR, LF, VT, FF, FS, GS, RS, U+0085, U+2028 and U+2029 is written as the visible text of its escape, as the CLI wrote the first five, and now writes all ten; a message of several lines still has one line per problem, and a `%o`, `%c` or other console format directive inside a Fault message or a Fact id no longer splices the cause into the console line.

## 1.0.0-rc.0

### Major Changes

- 99e06d3: The first release candidate of cf-loom 1.0.0, published to npmjs.com with access restricted to the @cf-loom npm organization: install it logged in with an npm account in that organization, with `@rc`.
