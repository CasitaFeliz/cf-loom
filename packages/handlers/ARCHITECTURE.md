## The runtime's seam

A Handler is a function carrying its `declaration`, the Endpoint, Guard, Command's Message Version or Subscription it was written for; what it was written with sits beside it, out of its type, so `serve` takes Handlers of every Endpoint or Guard through one parameter type. `./internal`'s `runEndpoint` and `runGuard` run the same call as a Direct call on what `serve` read: the Input and demands as the contract's reading parsed them, never parsed again, and the Context and Qualifier checked as a Direct call checks them; `endpointRunOf` and `guardRunOf` take how they check what they are given, as `messageRunOf` takes how it reads a body: `runEndpoint` and `runGuard` pass the check of what `serve` read, a Direct call the full check. They return how it went as a value for `serve` to answer: `invalid-call`, `invalid-outcome`, `thrown` (a throw, or a return that is no Outcome, as the Fault with its `cause`; a throw while checking what the call is given is not committed, since the implementation never ran) or `answered`, a Fault the Handler returned included; `serve` alone sends `thrown`, `invalid-outcome` and a returned Fault to `onServiceFault`. Inside `serve`, an Issue at `context` or `qualifier` is the runtime's own bug, since `serve` builds both: it answers it as a Fault and reports it to `onServiceFault`. A Direct call is that run plus a throw on the two invalid kinds. `runMessage` runs a Message Handler on a body as `consume` received it, read with its Reader alone, where a Direct call first writes its body back through it. `mappedHandlerOf` is the map check `serve` and `consume` share: the Handler the map holds as its own under a key, which `handle()` returned for that very declaration, or a throw naming the key, `endpoints.getOrder` or `commands.chargeCardV1`; `serve` runs it for every Handler in the map before the first request, `consume` before it pulls. `mappedMessageHandlerOf` is that check for a Message Handler plus the map's `readers`: a Message Handler keeps the Pairing it was written for beside it, and the check requires that the map's `readers` hold a Pairing under the same key and that the Handler was written for that very Pairing, by identity; it gives `consume` the Reader to read with. The identity check is what ties a Handler to the Readers file's Pairing.
