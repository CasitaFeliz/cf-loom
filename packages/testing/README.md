# @cf-loom/testing

`fakeProvider` and `FakeProviderError`, and their types (see [Types](#types)). cf-loom keeps its API test-friendly and ships testing helpers only where hand-written test doubles would drift from a Contract: this package fakes the Providers a Consumer depends on. How the package is built is in [ARCHITECTURE.md](https://github.com/CasitaFeliz/cf-loom/blob/main/packages/testing/ARCHITECTURE.md). Terms are defined in [CONTEXT.md](https://github.com/CasitaFeliz/cf-loom/blob/main/CONTEXT.md).

## Faking Providers

Each fake is checked against the Provider's Snapshot, as each Endpoint of its Contract Package carries it (see [The Contract Package](https://github.com/CasitaFeliz/cf-loom/blob/main/ARCHITECTURE.md#the-contract-package) in the root ARCHITECTURE.md), so a fake can never answer what the Provider could not:

```ts
import { fakeProvider } from '@cf-loom/testing';
import { paymentsDependency } from '../src/contract/dependencies/payments-service.dependency.ts';
import settlePaymentHandler from '../src/endpoints/payments/settle-payment.handler.ts';

const payments = fakeProvider(paymentsDependency);
payments.on('getPayment')
  .once((r) => r.reject('NOT_FOUND'))                    // getPayment lists notFound: a declared code, with its declared headers and body
  .once((r) => r.unknownRejection('CARD_EXPIRED'))       // a code the listed Endpoints do not declare
  .once((r) => r.fault({ committed: 'no', retryable: true, retryAfter: 30 }))   // 503 with Retry-After: 30
  .once((r) => r.noConnection())                         // the client infers the Fault: committed 'no'
  .once((r) => r.reset())                                // a reset after sending: committed 'unknown', retryable
  .once((r) => r.status(502))                            // committed 'unknown', not retryable
  .otherwise((r, { params }) => r.success({ id: params.paymentId, amount: 1200 }));

// the Handler under test asks getPayment until the Provider answers a Success; its Resource is a client over the fake
const resources = { payments: payments.client({ headers: { 'x-api-key': 'k' } }) };
await settlePaymentHandler({ params: { paymentId: 'pay-1' } }, {}, { resources });
payments.calls('getPayment');                            // the Input of each request the Handler made, in order
```

The Handler is called directly (see [Testing a Service's own code](https://github.com/CasitaFeliz/cf-loom/blob/main/packages/handlers/README.md#testing-a-services-own-code) in the handlers README), and the client the fake returns is the Resource it takes.

- **Requests.** `fakeProvider` reads each request as the Provider would (see [Over HTTP](https://github.com/CasitaFeliz/cf-loom/blob/main/ARCHITECTURE.md#over-http) in the root ARCHITECTURE.md), every Guard admitting it, since a step answers for its GuardHandlers. A request that fails answers the Provider's invalid-input Rejection, with the Provider's code, status and message and cf-loom's body, and takes no step. The client never sends Input that breaks its schema (see [What a call sends](https://github.com/CasitaFeliz/cf-loom/blob/main/packages/client/README.md#what-a-call-sends) in the client README), so through `payments.client()` only the requests the code sends reach the fake; `payments.fetch` reads whatever Request it is given.
- **Where requests go.** `fakeProvider(dependency, { baseUrl })` is reached at `baseUrl`, `https://<provider>.test` by default, its Endpoints' Provider, and `payments.client()` always calls it there; `fakeProvider` throws when it is created, as `client()` does, given a `baseUrl` that `client()` refuses, which is a bug, a Dependency with no Endpoint, written through a cast, or an Endpoint whose exported Snapshot cut is in a format it does not read (see [Consuming a Contract](https://github.com/CasitaFeliz/cf-loom/blob/main/packages/client/README.md#consuming-a-contract) in the client README). Only a request's path is compared, under the base URL's path, from any origin. It is matched against the Endpoints the Dependency lists, and one none of them matches is a mistake naming the request, since a Consumer's client cannot send it. Its winner is then taken among those and the ones their cuts list as `shadowing`, so routing precedence is the Provider's (see [Over HTTP](https://github.com/CasitaFeliz/cf-loom/blob/main/ARCHITECTURE.md#over-http) in the root ARCHITECTURE.md): when a Retired one wins it, the request is answered `RETIRED`, as `serve` answers it, and when any other the Dependency does not list wins it, it is a mistake. A test that wants `NO_SUCH_ENDPOINT` scripts it, `r.reserved('NO_SUCH_ENDPOINT')`.
- **Steps.** Each step, in `once` or `otherwise`, receives a builder typed by what a Caller of the Endpoint receives, so codes and bodies autocomplete from the Provider's Contract and nothing collides with `@cf-loom/contract` or `@cf-loom/handlers`, and the request's Input as the Provider parses it, its Guards' demanded headers and query params included, since a Provided Endpoint's Input merges them (see [The Contract Package](https://github.com/CasitaFeliz/cf-loom/blob/main/ARCHITECTURE.md#the-contract-package) in the root ARCHITECTURE.md). A step may be async.
  - `r.success(…)` answers the Success, given what `success()` takes for the Endpoint (see [EndpointHandler](https://github.com/CasitaFeliz/cf-loom/blob/main/packages/handlers/README.md#endpointhandler) in the handlers README), as a Caller reads it.
  - `r.reject(code, body?)` answers a code the Endpoint answers, a Standard one by the Provider's code, with its status and message, and its body when it declares one; a code that declares headers takes `r.reject(code, { headers, body? })`, as `reject()` of `@cf-loom/handlers` does.
  - `r.unknownRejection(code, { message?, headers?, body? })` answers a code the Endpoint does not answer, as a later Provider might send it. A code another listed Endpoint declares, itself or through a Guard it attaches, or the Provider's not-found code, is answered as declared, since a code keeps one status, headers and body shape across a Contract and adding it to this Endpoint is an Additive Change (see [Rejections](https://github.com/CasitaFeliz/cf-loom/blob/main/COMPATIBILITY.md#rejections) in COMPATIBILITY.md): its declared status, its declared message unless given, and its headers and body checked by their readers. Any other code is answered with status 422, its message the code unless given, and no body unless given, any JSON value; it has no headers to give. A code only an Endpoint the Dependency does not list declares is answered as any other, with 422, since the fake knows only the listed Endpoints.
  - `r.fault({ committed, retryable, message?, retryAfter? })` answers a Fault, as `fault()` of `@cf-loom/handlers` takes it, `cause` aside (see [EndpointHandler](https://github.com/CasitaFeliz/cf-loom/blob/main/packages/handlers/README.md#endpointhandler) in the handlers README), with status 503 when it is retryable and 500 otherwise, saying `Internal error` unless given a message; a retryable one given `retryAfter`, in whole seconds from 0, also carries `Retry-After`, as `serve` sends it, which the client's Fault exposes as `retryAfter`.
  - `r.reserved(code)` answers a Reserved code alone, with its status, `committed` and message; `METHOD_NOT_ALLOWED` also carries `Allow`, the other methods the listed Endpoints, and the ones their cuts list as `shadowing`, take on that path, which can be fewer than `serve` sends, empty when there is none (see [Over HTTP](https://github.com/CasitaFeliz/cf-loom/blob/main/ARCHITECTURE.md#over-http) in the root ARCHITECTURE.md).
  - `r.noConnection()`, `r.reset()` and `r.status(n, headers?)` let the client infer the Fault, as from a real response (see the inference table in [Over HTTP](https://github.com/CasitaFeliz/cf-loom/blob/main/ARCHITECTURE.md#over-http) in the root ARCHITECTURE.md): a refused connection, a connection reset after the request was sent, and a status from 200 to 599 other than the Success's, with no body; `headers` may carry `Retry-After`.
- **Scripts.** `once` adds a step that answers one request, in the order added; `otherwise` answers every request after them, and a later `otherwise` replaces an earlier one. An Endpoint's requests take their steps in the order they reached `fetch`, whichever is read first, and a step runs without waiting for another. A signal aborted while a request is answered makes `fetch` reject with its reason; a request aborted before it takes its step, while its body is read or while it waits for its turn, records no call, takes no step and holds no later request back. A script is never reset: a test creates its own fake.
- **Calls.** `payments.calls('getPayment')` lists the parsed Input of each request the Endpoint read as valid, its Guards' demands included, and `payments.invalidCalls('getPayment')` the Issues of each it answered with the invalid-input Rejection, `{ issues }`, each in the order they reached `fetch`; both are frozen copies, all the way down, so a step that changes its Input changes no record.
- **Mistakes in the test.** A mistake throws `FakeProviderError`, out of `fetch`, and the fake records it. The client passes it through unchanged (see [fetch and inferFault](https://github.com/CasitaFeliz/cf-loom/blob/main/packages/client/README.md#fetch-and-inferfault) in the client README), but the code under test may catch it like any error: a directly called EndpointHandler answers it as a Fault, as it answers any throw. `payments.verify()`, called at the end of a test or in `afterEach`, throws every mistake recorded so far, one a step made after its request was aborted included, and each Endpoint's `once` steps no request took (`getPayment: 1 once step left unused`): the one error, or an `AggregateError` of them, and again on every call. Its message names the Provider and the Endpoint when the request reached one, and what went wrong, then each Issue on its own line, as the contract writes an issue (see [Rejections](https://github.com/CasitaFeliz/cf-loom/blob/main/packages/contract/README.md#rejections) in the contract README), never the value. It is a mistake to call an Endpoint never scripted, or one with no step left and no `otherwise`; to script a value that breaks the readers, or one for a part the Endpoint or the code declares none of, a body on a 204 or on a code without one, or headers on a code without any, which lists `Expected no value` at that part; a header that cannot travel as text, or anything that throws while it is read; to give `r.reject` a code the Endpoint does not answer; to give `r.fault` a `committed`, `retryable` or `message` a Caller would not read as a Fault's, or a `retryAfter` `fault()` refuses; to give `r.reserved` anything but a Reserved code; to give `r.unknownRejection` a message that is no string, a code the Endpoint answers, a Reserved code or one that is no `UPPER_SNAKE_CASE` of at most 64 characters, which no Contract can declare, a body or headers that break the reader of a code the listed Endpoints declare, headers for a code they do not declare, or any other body that is no JSON value; to give `r.status` anything but an integer from 200 to 599 other than the Success's status, or headers that cannot be sent; to return from a step anything its `r` did not build, or to throw from one, what it threw kept as `cause`; and to send a request whose path lies outside the base URL's path, matches no Endpoint the Dependency lists, with that method or any, the methods its path takes named, or is won by one the Dependency does not list.

  ```ts
  const payments = fakeProvider(paymentsDependency);
  payments.on('getPayment').once((r, { params }) => r.success({ id: params.paymentId, amount: 1200 }));
  const resources = { payments: payments.client({ headers: { 'x-api-key': 'k' } }) };

  await settlePaymentHandler({ params: { paymentId: 'pay-1' } }, {}, { resources });

  payments.verify();                                     // every mistake, wherever the code caught it, and every once step left
  ```
- **Real client.** `payments.client(options)` returns a real client over the fake, and `payments.fetch` serves code that builds its own client with `client(dependency, { fetch })` (see [Consuming a Contract](https://github.com/CasitaFeliz/cf-loom/blob/main/packages/client/README.md#consuming-a-contract) in the client README), so the Consumer's code also runs the client's decoding: bodies and Success headers are validated against the generated readers, unknown codes arrive as `unknown-rejection`, Faults are inferred, and a Deprecated Endpoint sends the `Deprecation` header.
- **Values as a reader sees them.** Scripted Outcomes are written as a Caller reads them, and sent as the Provider would send them: written back through the Provider's generated readers, so their constraints are checked, their unknown keys stripped and each Unknown case turned into its text. Declared parts are checked against the Provider's schemas, shapes and constraints alike; an Unknown case, `{ unknown: 'refunded' }`, is checked only to make sure `'refunded'` is not a declared value, and a bare `'refunded'` where an Open Enum is declared breaks its reader. That is how a test reaches the code that handles values the Provider may add later.
- **Responses as `serve` sends them.** A fake answers with the status, the declared headers, the content type and the JSON value `serve` would send for the same Outcome, and every response of a Deprecated Endpoint, whatever it answers, carries `Deprecation`, from the `deprecatedAt` the exported Snapshot cut records.
- **Scope.** The package fakes only other Services. A Service's own Handlers, Guards and Messages are tested by calling them (see [Testing a Service's own code](https://github.com/CasitaFeliz/cf-loom/blob/main/packages/handlers/README.md#testing-a-services-own-code) in the handlers README) and with `memory()` (see [In memory](https://github.com/CasitaFeliz/cf-loom/blob/main/packages/messaging/README.md#in-memory) in the messaging README). An Event's body handed to a Handler is written as a Subscriber reads it, with Unknown cases written `{ unknown: … }`, and the Handler writes it back through the Reader and reads it again; what `deliver` takes is in [In memory](https://github.com/CasitaFeliz/cf-loom/blob/main/packages/messaging/README.md#in-memory) in the messaging README.

## Types

- `FakeProvider<D>`, what `fakeProvider(dependency, options?)` returns: `fetch`, an `Http`, `client(options?)`, `on(name)`, `calls(name)`, readonly all the way down, `invalidCalls(name)`, each name one the Dependency `D` lists, and `verify()`; `FakeProviderOptions`, `{ baseUrl? }`; `FakeClientOptions<D, Configured>`, what `client()` takes: `ClientOptions` without `baseUrl` and `fetch`, the fake's own, so a field it does not declare, those two included, is a type error, given as a literal or through a variable (see [Runtime](https://github.com/CasitaFeliz/cf-loom/blob/main/ARCHITECTURE.md#runtime) in the root ARCHITECTURE.md).
- `Script<D, Name>`, what `on(name)` returns, `{ once(step), otherwise(step) }`; `Step<D, Name>`, `(builder, input) => ScriptedAnswer | Promise<ScriptedAnswer>`, where `input` is the parsed Input of the Endpoint `D` lists as `Name`; `StepBuilder<D, Name>`, the builder a step receives, `r` in the examples, typed by what a Caller of that Endpoint receives, `ReceivedOutcome<D, Name>` (see [Types](https://github.com/CasitaFeliz/cf-loom/blob/main/packages/client/README.md#types) in the client README), the Provider's Standard codes and the invalid-input body by its Reader included: `r.success` takes what `success()` of `@cf-loom/handlers` takes for that Endpoint, as a Caller reads it, `r.reject` one code with the headers and body that code declares, so a code not narrowed to one is a type error, `r.fault` a Fault, with `retryAfter` only when `retryable` is `true`, and `r.reserved` a Reserved code; `ScriptedAnswer`, what only `r` builds. `Name` is a name `D` lists.
- `InvalidCall`, `{ issues }`, one request `invalidCalls(name)` lists.
