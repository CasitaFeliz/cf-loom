# Internals of @cf-loom/testing

How a fake (see [README.md](README.md)) answers a request, and how the package's `src/` is split into modules, as [Package layout](../../ARCHITECTURE.md#package-layout) in the root ARCHITECTURE.md requires. How an Outcome travels over HTTP and which Fault the client infers when there is none are in [Over HTTP](https://github.com/CasitaFeliz/cf-loom/blob/main/ARCHITECTURE.md#over-http) in the root ARCHITECTURE.md.

Its peers are `@cf-loom/contract`, `@cf-loom/client` and `zod`. `@cf-loom/handlers` and `@cf-loom/server` are devDependencies, so the tests build Handlers and compare a fake's responses with `serve`'s; `tsconfig.test.json` alone references them.

## Modules

The entry `src/index.ts` (`.`) re-exports from `faking/`, `mistakes/` and `scripting/`.

| Module | Holds | Depends on |
| --- | --- | --- |
| `mistakes/` | `FakeProviderError`, and a mistake's message: it names the Provider and the Endpoint when the request reached one, and what went wrong, then each Issue on its own line | none |
| `provided/` | each exported Endpoint's exported Snapshot cut, read first by the format it names and refused in a format cf-loom does not read or one its format does not describe; each Endpoint the package exports, matched as `serve` matches it, and each the cuts list as `shadowing`, which only decide the winner of a request an exported Endpoint matches, and each listed one prepared once: its packaged declaration, the nodes its text parts are read by, its `deprecatedAt` and its Rejections by code, and every code the Provider's Contract Package declares, by its resolved code; a request's path under the base URL's, matched to an exported Endpoint, then to the declared one that wins it: a listed Endpoint, with the other methods its path takes, a Retired one, or the test's mistake; who a mistake with a listed Endpoint names | `mistakes` |
| `scripting/` | `Script`, `Step`, `StepBuilder` and the one builder every step receives; the closed union of what a step scripts, held in a `ScriptedAnswer` no test can build; each Endpoint's steps, how many were added and left, and the turns its requests take them in | none |
| `answering/` | a scripted answer as the Provider sends it: a Success, or a Rejection, written back side by side through the readers of its shape, a code the Endpoint does not answer as the Contract Package declares it, or with 422 when it declares it nowhere, a Fault, read back as the Fault a Caller reads, a Reserved code, `METHOD_NOT_ALLOWED` with `Allow`, or a bare status as a `Response`, a network failure thrown as `fetch` throws it | `provided`, `scripting`, `mistakes` |
| `faking/` | `fakeProvider` and its types; one request top to bottom, read by the contract's reading, its `Deprecation` added once to whatever it answers; the calls each Endpoint received, those read as valid, each a frozen copy of its Input, and those answered invalid, each in arrival order; each mistake `fetch` throws, or a step makes after its request was aborted, recorded; `verify()`, which throws the recorded mistakes and each Endpoint's `once` steps no request took; an abort | all of the above |

The rules a fake shares with `serve` and the client live in `@cf-loom/contract`'s `./internal`: matching a request and reading its text parts and body, a request as its Provider reads it, writing a value back through a Reader schema, a part a writer gives, written back through its Reader and refused where the declaration gives it none, the shape of a Success or a Rejection, with what a step gives for it, by side, and its sides written back and their headers checked to travel as text, the invalid-input Rejection's response, the `Response` of each Outcome and the `Deprecation` header. The client is the real one, and `AnyDependency`, `ConfiguredName`, the base URL checked once and the path it prefixes come from its `./internal`; the grammar of a Rejection code and the Reserved codes, which a code the Provider does not declare cannot be, come from the contract's. An Issue's line comes from the contract's `./internal`, and a network failure as `fetch` throws it from the client's.

## A request

1. A signal already aborted rejects `fetch` with its reason, before anything is read, recorded or taken. The request's path, under the base URL's path, is matched against every exported Endpoint, and its winner taken among those and the `shadowing` ones; a Retired winner answers `RETIRED`, with no call and no step; a request outside the base URL's path, matching no exported Endpoint, won by a Private one or by an Endpoint the Dependency does not list, is the test's mistake.
2. Its place among the Endpoint's calls is kept, and its turn taken behind the requests that reached `fetch` before it.
3. It is read as the Provider reads it. What fails answers the invalid-input Rejection, its call recorded, and the request takes no step.
4. Once every earlier request of the Endpoint was read and took its step, if it had one, it takes the next, and its call is recorded: a `once` step, else `otherwise`, else none, the test's mistake. A request aborted before this point, while its body is read or while it waits, records no call, takes no step and gives up its turn; a request the test's mistake leaves with no step records its call and gives up its turn too.
5. The step runs, and what it scripted is sent as the Provider would send it, with `Deprecation` when the Endpoint is Deprecated, or thrown as `fetch` throws a network failure; whatever throws while it is read is the test's mistake, kept as `cause`. A signal aborted meanwhile rejects `fetch` with its reason.
