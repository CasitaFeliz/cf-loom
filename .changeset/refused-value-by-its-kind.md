A refusal shows a value that untyped code passed and its type does not allow by its kind, running none of the value's code. A limits setting or an `account` that `inProcess()`, `applyBrokerPlan` and `sqs()` refuse is shown as `util.inspect` prints it only when it is a primitive or a list held as data (its first 100 entries, three levels deep): an object reads `an object`, a function `a function` and any other list `a list`, so a refusal no longer prints every key of a wide object or throws what the value's `[inspect.custom]`, getter or Proxy trap threw in place of its own line naming the place; an object that used to print its keys (`{ seconds: 30 }`) now reads `an object`. A function in a declaration is named `a function` in a validation line, where its source was printed or a throwing `Symbol.toPrimitive` threw out of `generate` and `serve`. A Rejection's `code` and a returned `kind` that are no string are named by their kind in the `InvalidOutcomeError` and the Fault's `cause` of a Handler, instead of `[object Object]`, a function's source or what the value's `toString` threw.
