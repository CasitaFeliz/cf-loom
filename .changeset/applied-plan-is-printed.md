`applyBrokerPlan`, from `@cf-loom/messaging/jetstream` and `@cf-loom/messaging/sqs`, applies a Broker plan only when each Stream name, Durable consumer name, subject and Service name reads back into names the grammars accept (a Service name, event or command, a Message name and its version, a Subscription name) that the printers print again unchanged, under the Broker plan's `prefix`, and the Broker plan is the one Service's those names print, in code point order. It refuses any other before it connects, naming a place where it differs, so a name with a line break, a wildcard subject such as `staging.>`, a Durable consumer pointed at another Message Version's subject, a Durable consumer of a Subscription to the Service's own Event whose subject its Stream does not hold, or whose Stream the Broker plan lacks, a Broker plan that merges the Streams of two Services, a list out of order and a key named `__proto__`, which was dropped without a word, are refused. Broker plans that applied before and now do not: a script that merges two Services' Broker plans must call `applyBrokerPlan` once for each Service, and a Broker plan written by hand with names `cf-loom broker-plan` never prints must print them as it does.
