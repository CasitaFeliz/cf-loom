A first `check` or `publish`, of a package the registry does not know yet, takes the registry from the URL npm's 404 names, and asks `npm whoami` there, instead of asking `npm config get` which registry serves the package, which npm refuses under a `workspaces` setting and in a member of an npm workspaces root. Every npm call cf-loom makes runs with `--workspaces=null`, so a first `check` or `publish` works under `workspaces=true` from any `.npmrc` or `npm_config_workspaces`, and in a workspace member. When npm refuses `npm whoami` under a `workspace` setting, as it does unless the project is a member of a workspaces root, the run exits 3 with a line that names the setting, where it printed `npm config get @org:registry failed (ENOWORKSPACES: …)`. A package name npm prints redacted in its 404, because it holds a UUID or a token shape, is matched with the name cf-loom knows. A registry URL npm prints redacted fails with a line that says so: `npm view <package> failed: npm redacts a registry URL that holds credentials: …` for a password, `npm view <package> failed: npm redacted part of the registry URL (…), so cf-loom cannot name the registry to ask npm whoami` for a UUID or a token, and `npm view <package>'s 404 names no registry: …` for a 404 that names none, in place of `npm config get <key> failed: npm will not print a registry URL that holds credentials: …` and `npm did not say which registry serves <package>`.
